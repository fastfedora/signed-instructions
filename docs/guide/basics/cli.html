Command Line Interface (CLI)

The sib command creates keys, enrolls them, signs instructions, verifies files and decodes blocks. It runs in dev mode in Phase 1: every command that signs or verifies prints the dev-mode warning to standard error.

All commands read SIB_HOME for the directory that holds keys and the registry (default: ~/.sib).

Inside the repository, run it as uv run sib. After source .venv/bin/activate, or after uv tool install --editable ., plain sib works; the examples below use the plain form.

Basic Usage

# Create a dev key and enroll it for a signer
sib keygen --signer alice@example.com --enroll

# Sign an instruction given on the command line, writing the block to stdout
sib sign --signer alice@example.com --expires 2h --audience acme/dev-agent \
  --text "You may deploy the current main branch to staging whenever the test suite passes."

# Sign the contents of a file instead
sib sign --signer alice@example.com --expires 2h --audience acme/dev-agent --file instruction.txt

# Verify every block in a file for a given audience
sib verify CLAUDE.md --audience acme/dev-agent

# Decode blocks without verifying them
sib inspect CLAUDE.md

Commands

keygen

Create a dev-mode Ed25519 key under $SIB_HOME/dev-keys/ and optionally enroll it. Give --signer, --kid, or both.

--signer ID
The signer the key belongs to. When --kid is omitted the key identifier is derived as <signer>#dev-<year>-<month> (e.g., alice@example.com#dev-2026-09).
--kid ID
Key identifier, by convention signer#label. Overrides the derived name.
--enroll
Also add the public key to the registry. Requires --signer.
--dev
Accepted for clarity; dev mode is the only mode keygen supports.

enroll

Add an existing public key to the registry, for keys created elsewhere.

--signer ID
The signer the key belongs to. Required.
--kid ID
Key identifier. Required.
--public-key B64URL
The raw public key, base64url encoded. Required.
--alg ALG
Signature algorithm (default: EdDSA).
--dev
Mark the key as a dev-mode key. Without it the key is enrolled as enforced.

sign

Clearsign an instruction. The command prints the canonical text and the terms before signing, so what you see is what you sign.

Either identifier is enough: a --kid names its signer through the registry, and a --signer with exactly one enrolled key names that key. With several keys, the command lists them and asks for --kid.

--signer ID
The signer, written to the iss header field. Derived from --kid when omitted; checked for agreement when both are given.
--kid ID
The key to sign with. Derived from --signer when the signer has one enrolled key.
--expires DURATION
Validity window from now, as 30m, 2h or 1d (default: 2h).
--audience ID
The deployment or harness the block is for. Optional in dev mode; a block with no audience is refused in enforced mode.
--canon RULE
Canonicalization rule (default: text/1). See Canonicalization.
--text TEXT
The instruction, given directly. Line structure does not matter under text/1.
--file PATH
File holding the instruction, or - for standard input (default when --text is absent).
--out PATH
Write the block to a file instead of standard output.

verify

Extract and verify every block in a file. Exits with status 0 only when at least one block was found and every block verified.

FILE
The file to check, or - for standard input.
--audience ID
The audience of this harness; blocks for another audience fail with audience_mismatch.
--enforced
Verify in enforced mode: dev-mode blocks and keys confer nothing.
--json
Print the provenance manifest as JSON instead of the human-readable summary.

inspect

Decode every block in a file without verifying: the text as written, the clear metadata lines, the decoded header and the first characters of the signature.

FILE
The file to decode, or - for standard input.

Exit Codes

sib verify returns 0 when every block verified, 1 otherwise, including when no block was found. The other commands return 0 on success and exit with a message on a usage error, such as signing with a key that is not enrolled for the signer.

Environment

SIB_HOME
Directory for dev keys and registry.json (default: ~/.sib).
